## 背景

我有一个基于 Quartz v4 的个人博客（托管在 GitHub Pages），想实现这样的工作流：每天把学到的东西随手发给 AI，让它帮我整理成结构化的知识库文章并更新博客。

选择 OpenClaw 来做这件事，因为它可以本地运行、常驻后台、通过聊天软件交互，很适合当一个"知识编辑助手"。

## 需要解决的三个核心问题

### 1. 让 bot 知道怎么更新博客

bot 需要知道博客的技术细节，否则它不知道文件放哪、格式怎么写。

**做法**：写一个 `BLOG_INSTRUCTIONS.md` 放到 OpenClaw 的 workspace 里，内容包括：

- 仓库本地路径和分支（`v4`）
- 内容目录结构规则（`content/[领域]/[子领域]/文章.md`）
- Quartz 的 frontmatter 格式（title, date, tags, lang 等字段）
- 双语规则（中文主版本 `.md` + 英文翻译版 `.en.md`）
- Git 操作流程（add → commit → push，**且不能自动 push**）
- 明确列出禁止事项（不动配置文件、不删已有文章、不编造内容）

关键是把这个文件当作 bot 的"操作手册"，在 `SOUL.md` 里引用它，让 bot 每次处理博客任务前先读。

### 2. 规范化 bot 的行为

光知道技术操作还不够，还需要告诉 bot "什么时候做什么"和"怎么写"。

**做法**：写一个 `WRITING_GUIDE.md`，内容包括：

**触发词系统**——约定好聊天中的关键词对应什么行为：

| 我说 | bot 做什么 |
|---|---|
| `记一下：...` | 整理成博客笔记 |
| `发布：...` | 整理并准备发布 |
| `更新 [文章名]：...` | 在已有文章中追加内容 |
| `翻译 [文章名]` | 生成英文版 |
| 没有触发词 | 当普通聊天，不自动写文章 |

**写作规范**——定义文章风格：
- 学习笔记风：简洁直接，不过度润色
- 每篇必须有：核心概念、关键点、代码/示例（如有）、参考链接
- 不确定的地方标 `[TODO]`，不要瞎编

### 3. 审核和修改流程

我选了最轻量的方案——直接在聊天里审核：

Rose 发内容 → bot 整理成文章 → 在聊天里发给我预览 → 我说"可以" → bot 保存并生成英文版 → 英文版也发我看一眼 → 确认 → bot 执行 git push → 发布完成

如果我要改，就直接在聊天里说"改一下 xxx"，bot 改完重新发完整文章。

这个方案的好处是零额外工具，坏处是没有修改历史。如果以后需要更正式的流程，可以切到 PR 审核模式。

## 实际配置步骤

### 1. 在 OpenClaw workspace 里放入指令文件

macOS 下 workspace 目录是隐藏的（`.` 开头），在 Finder 里按 `Cmd + Shift + .` 可以显示隐藏文件，或者用 `Cmd + Shift + G` 直接输入路径跳转。

### 2. 在 SOUL.md 里引用

在 SOUL.md 添加一节：在处理博客相关任务前，先阅读 BLOG_INSTRUCTIONS.md 和 WRITING_GUIDE.md。

### 3. 确保 bot 能访问博客仓库

bot 需要有本地 clone 的仓库路径的读写权限，并且 git 已经配置好 push 的凭证。

## 知识库目录设计

因为我的知识库会不断扩展新领域，目录设计需要灵活。规则很简单：
- 文件夹名用英文小写 + 连字符
- 每个文件夹有 `index.md` 做概览
- 当一个领域积累 3+ 篇不同方向的文章时再拆子目录
- bot 负责定期检查结构是否需要调整

## 双语方案

Quartz v4 不原生支持文章级的语言切换按钮，所以用了一个简单方案：

- 每篇文章两个文件：`article.md`（中文）+ `article.en.md`（英文）
- 文章顶部各放一个链接互相指向对方
- frontmatter 里用 `lang` 和 `english`/`chinese` 字段标记对应关系
- bot 写完中文版后自动翻译生成英文版

后续如果想做组件级的切换按钮，需要自定义 Quartz 的 TypeScript 组件。

## 总结

核心思路就是：**把所有规则写成文档，让 bot 自己读**。不要试图在一次对话里口头交代所有事情，那样 bot 会忘。写成持久化的指令文件，bot 每次都能参考。

两个关键文件：
- `BLOG_INSTRUCTIONS.md`：技术层——怎么操作
- `WRITING_GUIDE.md`：行为层——怎么写、怎么审核
